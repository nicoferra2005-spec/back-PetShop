PASO 3 - CATEGORIAS, MARCAS Y ESPECIES

1. Que pide este paso

El paso 3 corresponde a la administracion de los datos que clasifican los productos:

- Categoria: por ejemplo Alimentos, Juguetes o Higiene.
- Marca: por ejemplo Royal Canin o Pedigree.
- Especie: por ejemplo Perro, Gato o Ave.

Estos datos son necesarios para que el paso 4 pueda crear productos asociados a una
categoria, una marca y una o mas especies.

La consigna pide una API REST que permita consultar la informacion completa o filtrada.
Por eso se implemento el CRUD de los tres recursos.

2. Que significa CRUD

CRUD representa las cuatro operaciones principales sobre los datos:

- Create: crear un registro nuevo con POST.
- Read: consultar registros con GET.
- Update: modificar un registro con PUT.
- Delete: eliminar un registro con DELETE.

Cada recurso tiene estas operaciones para poder administrarlo sin acceder directamente
a MySQL.

3. Como funciona una peticion

El recorrido de una peticion es:

Cliente HTTP -> Controller -> Service -> Repository -> MySQL

- El Controller recibe la peticion y define la URL y el codigo HTTP.
- El Service contiene las reglas de negocio y las validaciones.
- El Repository usa Spring Data JPA para consultar o modificar la tabla.
- MySQL guarda los datos en las tablas categoria, marca y especie.

Se separaron estas responsabilidades para que los controllers no tengan logica de
negocio y para que los siguientes integrantes puedan reutilizar los services.

4. Por que agregamos DTOs

Los DTOs son objetos que representan los datos que entran o salen de la API.

Se crearon DTOs Request para recibir datos y DTOs Response para devolver datos.
Esto evita devolver directamente las entidades JPA con sus relaciones hacia Producto.
Si se devolvieran las entidades completas, Jackson podria intentar recorrer las
relaciones en ambos sentidos y generar JSON demasiado grande o recursivo.

Tambien permite controlar que datos se muestran. Por ejemplo, nunca es necesario
devolver desde este modulo la lista interna de productos de una categoria.

7. Endpoints de categorias

GET    /api/categorias
GET    /api/categorias?soloActivas=true
GET    /api/categorias/{id}
POST   /api/categorias
PUT    /api/categorias/{id}
DELETE /api/categorias/{id}

Ejemplo POST:
{
  "nombre": "Alimentos",
  "descripcion": "Alimentos para mascotas",
  "habilitada": true
}

El parametro soloActivas=true devuelve solamente categorias con habilitada=true.
Sin el parametro se devuelven todas, ordenadas alfabeticamente.

8. Endpoints de marcas

GET    /api/marcas
GET    /api/marcas?soloActivas=true
GET    /api/marcas/{id}
POST   /api/marcas
PUT    /api/marcas/{id}
DELETE /api/marcas/{id}

Ejemplo POST:
{
  "nombre": "Royal Canin",
  "habilitada": true
}

El filtro de marcas funciona igual que el de categorias.

9. Endpoints de especies

GET    /api/especies
GET    /api/especies/{id}
POST   /api/especies
PUT    /api/especies/{id}
DELETE /api/especies/{id}

Ejemplo POST:
{
  "nombre": "Perro"
}

Las especies se ordenan por nombre y no se permite crear dos especies con el mismo
nombre, sin distinguir mayusculas de minusculas.

10. Validaciones y respuestas HTTP

- Nombre vacio: HTTP 400 Bad Request.
- Especie repetida: HTTP 400 Bad Request.
- Recurso inexistente: HTTP 404 Not Found.
- Alta exitosa: HTTP 201 Created.
- Consulta o modificacion exitosa: HTTP 200 OK.
- Eliminacion exitosa: HTTP 204 No Content.

La excepcion RecursoNoEncontradoException se conecta con GlobalExceptionHandler para
que un error de negocio se transforme en una respuesta HTTP clara para el cliente.

La eliminacion es fisica. Si una categoria, marca o especie ya esta siendo utilizada
por un producto, MySQL puede impedir la eliminacion por la clave foranea. En ese caso
se debera conservar el registro o aplicar una baja logica en una etapa posterior.

11. Como se verifico

- Se compilo todo el proyecto con Java 17 usando mvnw.cmd clean test-compile.
- Se comprobo que MySQL respondiera en localhost:3306.
- Se comprobo que Spring Boot respondiera en localhost:8080.
- Se probaron las altas, consultas, modificaciones y eliminaciones de los tres
  recursos.
- Se probo la respuesta 400 para especies duplicadas.
- Se probo la respuesta 404 para un id inexistente.
- Los registros usados para las pruebas fueron eliminados y las tablas quedaron
  nuevamente vacias.

12. Que no incluye este paso

Este paso no implementa productos, imagenes, carrito ni checkout. Esos modulos usan
las categorias, marcas y especies creadas aqui, por lo que este trabajo deja lista la
base funcional para los pasos siguientes.

13. Como ejecutar

1. Iniciar MySQL.
2. Abrir una terminal nueva en la raiz del proyecto.
3. Ejecutar:
   .\mvnw.cmd spring-boot:run
4. Probar los GET desde el navegador o usar Thunder Client/Postman para POST, PUT y
   DELETE.

Todavia no se hizo commit ni push. El cambio debe revisarse localmente antes de
subirlo a GitHub.
